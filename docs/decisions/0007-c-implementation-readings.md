## 固定する読み方

1. **C1b の分母が 0 本のとき（判定に関わる）**: 0006 は C1a にだけ「個人×新参のトレンド入りが 0 本なら『3 以上』として扱う」と書いた。C1b も分母は同じ個人×新参なので、**同じ扱いにする**: 個人×新参のトレンド入りが 0 本で、個人×実績ありが 1 本以上なら「3 以上」として扱い、分母の率の 95% 上限（3 ÷ 記事数）を併記する。C1a・C1b とも、分子と分母の両方が 0 本、またはどちらかの層が空なら判定不能
2. **記事の同一性は slug で決める**。パスの先頭は記事を Publication に移すと変わるため、パスでは同じ記事が 2 本に数えられうる
3. **Publication の値**: トレンドに出た記事は、トレンドの初観測時の値。出なかった記事は、`latest_feed` に最初に現れたときの値（0006 の「食い違えば `trend_feed` を優先」の具体化）
4. **「連続するスナップショットの間隔」は、完全なスナップショット（A''-1 を満たす回）どうしで測る**。失敗した回は何も観測していないため。除外が増える側（保守的）の読み方。除外するのは `published_at` が区間の内側（両端を含まない）にある記事
5. **誕生コホートは `latest_feed` に最初に現れた回の値で決める**。トレンド側が失敗した回でも、新着が取れていれば新着は使う
6. **著者データが取れなかった個人の記事は層「不明」**とし、C1・C2 の層別から除いて件数を書く。Publication 記事は著者データが無くても層が決まるので残す。A''-2（95%）がこの欠けの上限を保証する
7. **過去平均は `published_at` が厳密に前の記事だけで計算する**。副の層（過去平均 4 層）では、初投稿を 0 として「<1」に入れる（0001 の式 `(total − その記事) ÷ max(n − 1, 1)` が初投稿で 0 になるのと同じ結果）
8. **C2 で初観測時の `liked_count` が欠けた記事は除き、件数を書く**（今日までの実データでは 0 件）
9. **T_end より後のスナップショットは一切使わない**。トレンド入り・初観測・滞在のどれも T_end まで。T_end の時点でまだトレンドに居た記事の数を、滞在の右側打ち切りとして書く
10. **A''-2 の分母**は「誕生コホート（72 時間）の著者 ＋ トレンド記事の著者」、分子は記事一覧とユーザー API の**両方**が 200 の著者
11. **分位点は線形補間**（両端を含む方式）。中央値は通常の定義と一致する
12. **C3(a) に「初観測が公開から 72 時間／168 時間より後だった記事の割合」を添える**。コホートの打ち切り（72 時間、頑健性 7 日）が足りていたかの確認で、記述のみ
13. **C3(d) の「取得時点のいいね」は著者の記事一覧の値**を使う。一覧に無い記事（削除・非公開、または著者データの欠け）は除いて件数で分かるようにする
