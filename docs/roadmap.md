## 全体方針

**「当たるか」より先に「検証できるか」を確保する。**（前題材 funding-arb-jp、patent-equity、meccha-chameleon と同じ）

- 問いと判定基準はデータを見る前に固定し、見た後に変えない
- 数値と事実には出典 URL と確認日を付ける。未確認は「未確認」と書く。事実と推測を分ける
- 取得は 1 リクエスト/秒以下。User-Agent に個人の調査であることを書く。非公式 API は運営が容認しているが仕様変更は予告なし（[sources.md](sources.md)）
- 公開するのは集計だけ。記事の本文は取得しない。著者名は集計に出さない
- 目的は 2 つ: (1) Zenn の記事として公開できる定量事実を出す、(2) 自分の記事作成に生かす（何を、いつ書くか。どの導線を持つか）

### 見直しの規則

- 見直しは **フェーズ 1 の取得を始める前に 1 回だけ** 許可する。差分は `decisions/` に記録する
- **禁止**: 取得を始めた後に閾値・定義・対象トピックの選び方を変えること
- **禁止**: 結果が出た後に「このトピックは特殊だから外す」と対象を絞ること。外すのは事前登録した除外規則に該当する場合だけ
- **禁止**: C を満たすために問いを後から追加すること。問いは下の事前登録分に限る

## 問いの事前登録（指標の定義）

### 対象トピック（機械的に決める。手で選ばない）

フェーズ 0 の候補 39 トピック（[sources.md](sources.md) の「new」群）のうち、次をすべて満たすもの:

1. 一覧 API で全履歴に到達している（`full_history = true`）
2. **誕生月** = そのトピックの月間記事数が初めて **10 本以上**になった暦月（JST）。誕生月が **2024-01 以降 2025-08 以前**（経過月 11 まで観測できる）
3. 記事総数 100 本以上

除外規則（事前登録）: 誕生月の前に累計 50 本以上ある（つまりツール以前から同名のトピックが使われていた）場合は除外する。例として cursor（最古 2021-12-15）が該当しうる。該当の有無はデータで決める。

対照トピック: react, python, typescript, nextjs, aws, docker, go（成熟。一覧の上限で直近 1〜2 年に届く）。

### 記号

- `n(t, m)` = トピック t の誕生月から m ヶ月目（m = 0, 1, 2, …）に公開された記事数
- `R10(t, m)` = そのうち `liked_count ≥ 10` の割合（tabayashi と同じ「届いた」の定義）。同様に `R5`、`R1`、`BM1`（`bookmarked_count ≥ 1`）
- 早期 = m ∈ {0, 1, 2}、後期 = m ∈ {6, …, 11}
- 著者層 = 著者の過去平均いいね ＝ (`total_liked_count` − その記事の `liked_count`) ÷ max(`articles_count` − 1, 1)。層は tabayashi と同じ **<1 / 1〜5 / 5〜20 / 20 以上**。取得時点の値なので「未来の実績」が混ざる（既知の限界、結論に添える）
- 文字数層 = `body_letters_count` **<2,000 / 2,000〜5,999 / 6,000 以上**
- Publication = 一覧の `publication` が null でない

### 指標

| 問い | 指標 | 出し方 |
|---|---|---|
| **B1** 先行者利得（全体） | 早期 ÷ 後期 の到達率比、著者層と文字数層で層別して合算 | 対象トピックを合算し、層ごとに `R10(早期) / R10(後期)` を出し、後期の記事数で重み付けした比。**1.5 以上**なら「先行者利得あり」、未満なら「なし」 |
| **B2** 新参への適用 | 著者層「<1」に限った早期 ÷ 後期 | 同上を `R5` で（新参層は `R10` がほぼゼロのため）。1.5 以上なら「新参にも効く」 |
| **B3** 差の差 | 対照トピックの同じ暦月で同じ比 | 対象トピック t の早期・後期に対応する暦月を対照に当てはめ、`R10(早期暦月) / R10(後期暦月)` を出す。B1 の比 ÷ B3 の比が **1.5 以上**なら age 効果（古い記事ほどいいねが溜まる）では説明できない、と書く。未満なら B1 は age 効果と区別できないと**必ず書く** |
| **B4** ピークの位置 | `R10(t, m)` が最大になる m | トピック別に表にする。供給 `n(t, m)` の推移と並べる |
| **B5** 供給と希釈 | `n(t, m)` と `R10(t, m)` の順位相関（トピック内） | トピック別。負なら「増えるほど薄まる」 |
| 副 | ブックマーク率 `BM1` | B1〜B4 を `BM1` でも出す（保存型の記事の指標） |

既知のバイアス（結論に必ず添える）: `liked_count` は取得時点の累計で、古い記事ほど蓄積している（B3 で粗く確かめるだけ）。著者の実績は取得時点の値。トピックは著者が付けたタグで、後から付け直せる。誕生月は上の規則で機械的に決めたもので、ツールの発表日ではない。

## C（前向き収集）の設計

- 取得元: 公式 RSS `https://zenn.dev/feed`（「現在Zennでトレンドとなっている投稿」20 件、Zenn 公式 2020-09-29）。加えて各記事の `api/articles/{slug}`（いいね・ブックマーク・トピック・著者・Publication）と `api/articles?order=latest&count=48&page=1`（新着 48 本の対照プール）
- 頻度: 毎時（GitHub Actions の cron）。1 回 ≈ 22 リクエスト、1 req/s
- 保存: `trend_feed/YYYY-MM-DD.jsonl`（1 行 1 回）と `latest_feed/YYYY-MM-DD.jsonl`。リポジトリにコミットして永続化
- 最初の成果物（2 週間後）: トレンド入りした記事の著者の過去平均いいね・フォロワー数の分布。「過去平均 1 未満の著者の記事」の割合を出す
- 次（4 週間後）: トレンド入り前後のいいねの推移と、公開からトレンド入りまでの時間
- 判定はまだ登録しない。C の問いと基準は、収集を始めてから **データを見る前に** 別の決定記録で登録する
- **注記（正直に）**: 2026-09-04 12:10 のローカル動作確認で、トレンド上位 5 件の著者名・Publication・いいね数を表示してしまった（5 件中 4 件が Publication 所属、いいねは 4〜17）。C の基準を決めるときは、これを見た前提で書く。GitHub Actions は 2026-09-04 13:33 JST の初回実行から毎時動いている

## やらないこと

- 記事本文の取得と LLM による品質評価（krbrr が実施済み。本プロジェクトの問いに不要）
- タイトルの型の分析、公開時刻・曜日の分析（tabayashi が決着済み）
- 非公式のトレンド API（第三者）の利用。トレンドは公式 RSS だけを使う
- `/search` の利用（robots.txt で禁止）
- 個人の著者名を集計結果に出すこと
