# 0004. Q1b（持ち越し）の定義を修正する: 「初ヒット前」の窓は定義上ゼロで比が作れない

- 日付: 2026-09-05 11:20 JST（著者履歴の取得中。**Q1・Q2 のどの指標もまだ見ていない**）
- 状態: 採用

---

## 何が問題か

0003 の Q1b は「初ヒット後 3 本の R10 ÷ 初ヒット前 3 本の R10」と定義した。しかし k0 を**初**ヒットの番号とした時点で、k0 より前の記事にいいね 10 以上のものは存在しない。前 3 本の R10 は恒等的に 0 で、比は定義できない。対照（ヒットが無い著者）も同じく R10 が恒等的に 0 になる。集計コードを書いていて気づいた。

0003 の「見直しは取得を始める前に 1 回だけ」の規則には反するが、これは閾値や対象の変更ではなく、定義が数学的に成立していない箇所の修正である。修正はデータを見る前に行い、ここに記録する。

## 修正後の Q1b

**問い**: 初ヒットした著者は、ヒットしなかった著者に比べて、次の 3 本が届きやすいか。

| 項目 | 定義 |
|---|---|
| 処置群 | 初ヒット（`liked_count ≥ 10`）が k0 番目（k0 ≥ 2）で、k0 の後に 1 本以上ある著者。観測窓 = k0+1〜k0+3 本目（存在する分） |
| 対照群 | k0+1 本以上書き、1〜k0 本目にヒットが無い著者（初ヒットが k0 より後、または無い）。観測窓は同じ k0+1〜k0+3 本目 |
| 指標 | 処置群の観測窓の R10 ÷ 対照群の観測窓の R10。**k0 の記事の公開四半期で層別**し、処置群の観測窓の記事数で重み付けして合算（暦の効果を揃える） |
| 判定 | **1.5 以上**なら「持ち越しあり」、未満なら「持ち越しは無い」。閾値は 0003 のまま |
| 副指標 | 同じ比を R5 で。層別しない粗い比。**プラセボ**: k0−3〜k0−1 本目の R5（いいね 5〜9 の割合）を処置群と対照群で比べ、処置群がもともと「温かかった」かを見る |

対照群には「k0+1 本目以降でヒットする著者」を含む（含めないと対照の R10 が 0 になる）。これは「ヒットしなかった著者のその後のハザード」そのものであり、持ち越しの比較相手として妥当。
